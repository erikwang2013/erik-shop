## 1. Server Business API (service/)

### Current Status Summary
The infrastructure and security/payment/search/recommendation skeleton is solid (39 controllers + 111 models + 14 middleware + 10 scheduled tasks, Stripe/PayPal genuinely usable, 22 unit tests passing), but multiple capabilities the documentation claims are "complete" are actually placeholders or not wired up: Klarna/Adyen gateways are config-only, order placement doesn't calculate coupons/shipping/tariffs/risk control, read/write split is not enabled, and missing business seed data means core endpoints have no data after a fresh install.

### Implemented
- Dual payment gateway implementation (real code): in PaymentGateway.php, Stripe (PaymentIntent + webhook signature verification + refunds) and PayPal (REST v2 OAuth2 + order/capture/refund + verify-webhook-signature five-field verification + refund capture id parsing) are fully runnable; PaymentController::webhook uses an order status atomic latch to prevent duplicate posting and generates PlatformSettlements settlement records inside a transaction
- Payment chain closed loop: PaymentController (create/status/methods/webhook), AdminOpsController::executeRefund actually executes gateway refunds and persists to DB in a transaction (refund record + payment record + order status + logs), PaymentReconcileCron reconciles pending payments older than 2 hours against the gateway's real status every 6 hours
- 14-layer middleware stack in effect in order (config/middleware.php): Cors→Security (security-php SecurityGuard 25+ class detectors + Redis brute force counters)→RateLimit (Redis sliding window, 6+ endpoint rules)→Platform (8-platform identification)→GeoIp (MaxMind)→Locale→HashidsDecode→VersionRoute (API-Version header)→HashidsEncode→Encryption, route-level PosterVerify/JwtAuth/AdminKey
- Multi-currency pricing and multilingual products genuinely implemented: ProductSkuPrices per-currency independent pricing + ExchangeRates rate fallback, ProductTranslations eager loaded by locale (ProductController includes VAT incl./excl. tax display price calculation)
- Tariff estimation genuinely usable: TariffController calculates duty/vat via ProductHsCodes→TariffRules(dest_country+hs_code)→VatSettings (including duty-free thresholds and disclaimer); ShippingController calculates shipping by logistics zone + weight tiers
- Search and recommendation genuinely implemented: SearchController uses webman-scout (Products model Searchable + ES mapping erik_shop_products), falls back to MySQL LIKE with SearchLogs on ES errors; RecommendationCron calculates Top10 from purchase co-occurrence over the last 90 days into product_recommendations, RecommendationController item-based CF + popular fallback
- Core order flow: store atomically deducts stock inside a transaction (where stock>=qty decrement, prevents overselling), cancel restores stock, KYC/prohibited-country interception entry points, state machine 0-8; CouponController::claim row lock lockForUpdate + atomic latch prevents over-issuance
- All 10 scheduled tasks registered in config/process.php (exchange rate/shipment tracking/Feed/recommendation/compliance/return timeout/price alert/payment reconcile/settlement/multi-platform sync), all with error logging and skip logic when unconfigured
- Document export genuinely usable: ExportController PhpSpreadsheet XLSX+CSV (with HS Code column), DocumentController commercial invoice/packing list (dompdf), HealthController liveness probe (db/redis dual check)
- Quality toolchain complete: PHPUnit 12.5 (22 tests/45 assertions, 4 files: Security/Jwt/ApiResponse/RedisFacade), phpstan level 5 (phpstan.neon includes Eloquent false-positive exemptions), php-cs-fixer, .github/workflows/ci.yml (PHP 8.3/8.4 + MySQL + Redis matrix)
- Infrastructure patterns genuinely applied: BaseModel Snowflake primary keys, Hashids encode/decode middleware automatic conversion, Jwt.php access/refresh dual tokens (JwtAuth rejects refresh tokens for business endpoints), encryptable field encryption, config/risk.php + country.php + geoip.php operations configs complete

### Gaps
- Klarna/Adyen/Afterpay are placeholders only: PaymentGateway::make() match only supports stripe/paypal (default throws), PaymentController::methods explicitly filters to return only stripe/paypal (comment admits "avoid exposing unimplemented gateways"); but docs/api.md 6.1 response example contains a Klarna line and features.md 1.0 claims Klarna BNPL/Adyen — documentation and code are inconsistent
- Order placement doesn't integrate coupons/shipping/tariffs/risk control: OrderController::store only sums product subtotals, doesn't read the documented coupon_id (api.md 5.3), doesn't calculate the existing erik_orders shipping_fee/tax_amount/discount_amount/insurance_fee fields; config/risk.php exists but no RiskEngine is called anywhere in app/ (features.md 3.3 claims "calculates price (per-currency + coupon)" and "risk scoring (RiskEngine::score)")
- Business seed data missing: install.sql only has 2 INSERTs (wa_options/wa_roles system tables), erik_hs_codes/erik_tariff_rules/erik_payment_gateway_methods/erik_shipping_zones/erik_countries all have no data; database/seeders only has countries.php and no code loads it (dead file, CLAUDE.md claims coverage of countries/HS Code/exchange rates/logistics zones/compliance categories/size charts/risk rules) — after a fresh install, countries/payment methods/shipping/tariff endpoints return empty
- Read/write split config not enabled: config/database.php defines mysql_rw (2 read replicas + sticky) but no code in app/ or config/ references that connection name, all models use the default mysql; features.md 5.x claiming "DB read/write split (2 read replicas + sticky) complete" is inaccurate
- Subscription orders and multi-platform listings are schema-only: Subscriptions/SubscriptionOrders/SubscriptionLogs, PlatformListings models exist but have no controllers/routes/write code (multi-platform only has PlatformOrderSyncCron pulling orders via external URLs); features.md claims both are "complete"
- ES multilingual search overclaimed: CLAUDE.md claims "ES index contains all language title/description weighted by locale", but Products::toSearchableArray() only indexes basic single-language fields; the app/search/ directory CLAUDE.md claims actually doesn't exist (Searchable is inlined in the model)
- Customer service WebSocket IM not implemented: only ChatSessions/ChatMessages table structures (features.md admits "WS pending", consistent but indeed unfinished), and the order state machine "pending review (8)/refunding (6)" has no write paths (no review flow, refunds only go admin executeRefund straight to refunded (7))
- Test coverage narrow and inconsistent with documentation claims: only 4 unit test files (AUDIT-REPORT.md admits "no integration tests/no coverage report"), no controller/order/payment/middleware integration tests; api.md 13.18 says export returns CSV but the code defaults to XLSX with optional CSV; the api.md 2.1 documented min_price/max_price filter parameters are not implemented in ProductController::index

### Risks
- Payment chain lacks idempotency and event coverage: POST /api/payment/create has no idempotency key, repeated requests generate multiple pending payment records; webhook only handles payment_intent.succeeded / PAYMENT.CAPTURE.COMPLETED, refunded/failed events silently ignored, relying on PaymentReconcileCron (only checks orders older than 2 hours) as fallback
- Settlement dual-source drift: webhook and SettlementCron read rates from config('payment.gateway_fee.*') and config('cron.payment_gateway_fee_*') respectively, two independently maintained places; and after the webhook generates PlatformSettlements(status=0), SettlementCron recomputes with order_id deduplication, with duplicate/inconsistent calculation risks; settlement only covers platform commission + gateway fee, supplier_amount has no payout flow, affiliate_amount is always 0, multi-currency settlement (docs/08-multi-currency-settlement) is not a closed loop
- Fresh deployment means empty data + compliance default allow: all business seeds missing, config/country.php blocked_countries defaults to an empty array, kyc_required_countries is KR-only, OrderController's prohibited-country/KYC interception depends on manual configuration, misconfiguration means fully open
- Fragile search dependency: when ES is unavailable the whole try/catch falls back to MySQL LIKE, scout sync has no queue (config/scout.php sync.queue=false), index and multilingual analyzers have no CI coverage, index drift uncontrollable
- Financial precision and state machine gaps: order amounts use float accumulation round; refunds are full-order status=7 only with no partial refunds; the Refunds state machine 2 (rejected)/3 (refunded) only transitions through the single AdminOpsController path, no user-side refund application and review endpoints (the features.md 3.5 return flow review/label steps depend on the admin side)

### Suggestions
- [High] Complete business seed data: wire database/seeders/countries.php into the Web installation wizard or first-startup flow, and add the HS Code base library, default payment methods (stripe/paypal method rows), VAT/tariff rule examples, logistics zone seeds; otherwise fresh deployments have core endpoints (countries/payment methods/tariff/shipping) returning empty
- [High] Open up real order billing: OrderController::store integrates coupon discounts (coupon_id already documented), shipping_fee/tax_amount/discount_amount persistence (fields already exist), aligned with features.md 3.3/api.md 5.3, and implements the api.md 2.1 min_price/max_price filters
- [High] Converge payment method claims: pick one — implement the Klarna/Adyen gateways (PaymentGateway::make extension, Klarna config and gateway_fee already ready) or clearly mark "placeholder" and fix the api.md 6.1 example, avoiding the frontend displaying unavailable methods; also add an idempotency key to payment/create (order_id+gateway deduplication)
- [Medium] Implement the risk engine: implement RiskEngine::score (per config/risk.php checks/velocity), side-channel scoring on order/payment events writing risk_logs + order.risk_score (fields exist), connecting the "pending review (8)" state and manual review flow
- [Medium] Enable read/write split or fix the documentation: explicitly switch read-only queries to the mysql_rw connection (config ready), or at least mark "configured but not enabled" in features.md, eliminating the disconnect between config and implementation
- [Medium] Add integration tests and coverage gates: write PHPUnit integration tests for order creation (transaction/stock deduction/cancel), payment webhooks (signature verification/idempotency/settlement), Tariff/Shipping calculations, Hashids encode/decode (CI already has MySQL/Redis services to reuse directly), and configure coverage thresholds
- [Medium] Unify settlement rate sources and complete settlement: merge webhook and SettlementCron into a single rate config; add supplier/affiliate settlement writes (MerchantSettlements/SupplierSettlements/AffiliateCommissions tables exist) and payout/withdrawal flows, supporting the docs/08-multi-currency-settlement multi-currency settlement
- [Low] Platform and customer service WS expansion: add amazon/eBay/Shopee adapters to PlatformOrderSyncCron and implement product listing writes to PlatformListings (tables ready); customer service IM implements the WebSocket server and message send/receive (ChatSessions/ChatMessages tables ready)

## 2. Admin Console (admin/)

### Current Status Summary
The admin console is based on webman-admin + LayUI/Pear Admin with a complete installation wizard, RBAC permissions, WAF middleware stack, and a skeleton of 82 controllers/76 models, but the business layer is "controllers without pages": of the 67 mall controllers, 59 are pure CRUD stubs bound only to models, and apart from the cross-border panel there are no HTML views at all (menu clicks return 404), and ShopOrder/ShopPayment controllers fail at class load with fatal errors under PHP 8.3 due to incompatible method signatures, making the order/payment menus actually unusable.

### Implemented
- All 82 controllers (15 system + 67 shop) and 76 models (9 system + 67 shop) exist in pairs with Copyright headers, namespaces following plugin\admin\app\controller|model
- Generic CRUD base class Crud fully implements select/insert/update/delete with tree/select/normal formatting, including data permissions (dataLimit: personal/auth), desc table structure field whitelist filtering inputFilter, password hashing, afterQuery/insertInput/updateInput extension points
- Web installation wizard InstallController genuinely usable: step1 creates the database + validates conflicting tables + imports root install.sql (117 tables) + generates plugin/admin/config/database.php and thinkorm.php + generates service/.env and admin/.env (random JWT/Hashids/AES/ADMIN_API_KEY) + SIGUSR1 reload; step2 creates the super admin bound to role 1; importMenu recursively imports config/menu.php into wa_rules
- Permission system complete: AccessControl middleware + plugin\admin\api\Auth::canAccess (noNeedLogin/noNeedAuth/role rule matching/super admin * wildcard/401 and 403 routing), depending on wa_roles/wa_rules/wa_admin_roles tables
- Middleware stack consistent with features.md 4.2: SecurityMiddleware (erikwang2013/security-php SecurityGuard + login brute force 5/300s + security response headers), PlatformMiddleware (8-platform UA identification), HashidsDecode/HashidsEncode (request decode and response *_id field encode), AccessControl
- Menu structure config/menu.php (526 lines): 6 system groups + 7 business groups — data analysis/mall management/order management/customs & tax/logistics management/marketing management/supply chain management — 27 mall menu items total, with weights/icons/routes
- Cross-border panel ShopDashboardController + ECharts view (Pear Admin theme, KPI cards and 5 chart containers, referencing the echarts@5.5.0 CDN)
- Refund approval ShopRefundController is one of the few controllers with real business logic: state machine 0 pending/1 approved/2 rejected/3 refunded, calls the service internal endpoint POST /api/admin/refunds/{id}/execute (X-Admin-Key auth, service-side AdminOpsController + AdminKeyMiddleware genuinely exist) before marking refunded, refuses to persist on failure
- Order export ShopExportController: PhpSpreadsheet generates Excel (order number/date/status/currency/product amount/discount/shipping/paid amount), barryvdh/laravel-dompdf generates commercial invoice PDF (with items, currency, customs declaration notice)
- Models uniformly based on Snowflake primary keys (Base::boot creating auto-generates string-type IDs), business models declare erik_ table names and share the same MySQL connection as service (plugin.admin.mysql)
- i18n base files exist: zh_CN/zh_HK/en/ja/ko five languages with 48 keys each under admin/resource/translations
- Quality and deployment support: composer.json includes phpunit ^12.5 and php-cs-fixer dev dependencies, admin/Dockerfile + docker-compose (port 8788) fully configured

### Gaps
- **Fatal defect (reproduced in testing)**: ShopOrderController.php and ShopPaymentController.php override parent Crud methods with incompatible signatures (missing : array / : Response return types), PHP 8.3 Fatal error at class load — the "order list"/"payment records" menus crash on access and take the webman process down with error reports
- Of the 67 mall controllers, 59 are pure CRUD stubs containing only protected $model, and apart from ShopDashboardController there are no index() methods and no HTML views (view/shop/ only has dashboard/index.html); menu hrefs like /app/admin/shop/ShopProduct/index point to non-existent actions, webman's default exact-match routing falls into fallback 404 — the entire mall management UI (products/categories/logistics/marketing etc.) is actually unusable, JSON API only
- Cross-border panel data chain doubly broken: the view fetches /app/admin/shop/shop-dashboard/kpi and /chartData (kebab-case) with no matching routes (class name is ShopDashboardController, verified webman App::getController matches by filename exactly); and ShopDashboardController::kpi/chartData call $this->json(['code'=>0,...]) passing an array, conflicting with Base::json(int $code,...) signature and necessarily throwing TypeError; the region distribution/currency share/order status three charts are hardcoded sample data (code comments mark "sample data"), and the "logistics timeliness" chart CLAUDE.md claims doesn't exist
- Documentation claims inconsistent with code: packing list PDF, financial report PDF (per-currency summary) have no implementation at all in admin; shipping management ShopShipmentController is a pure stub (no HS declaration and tracking logic); order export Excel columns (ShopExportController.php lines 44-60) have no HS Code/tariff columns, inconsistent with CLAUDE.md "includes HS Code/tariff/currency"; product "multilingual editing + per-currency pricing" has no corresponding UI (ShopProductTranslation/ShopProductSkuPrice are stubs and not in the menu)
- 40 shop controllers not in menu.php (ShopMerchant/ShopPlatformAccount/ShopPlatformListing/ShopPlatformOrder/ShopRiskRule/ShopRiskLog/ShopCms/ShopGiftCard/ShopMembership/ShopPointRule/ShopSubscription/ShopB2b/ShopAbTest/ShopCountry/ShopCurrency/ShopExchangeRate/ShopEmailTemplate/ShopNotification/ShopOperationLog/ShopUserKyc/ShopSetting/ShopOrderDocument/ShopSizeChart/ShopKnowledgeBase/ShopFaq/ShopProductAttr/ShopProductCompliance/ShopProductFeed/ShopPriceAlert/ShopPrivacy/ShopInsurance/ShopInventoryTransfer/ShopApiDoc/ShopShop/ShopMerchantProduct/ShopMerchantSettlement/ShopCountryCompliance/ShopProductHsCode/ShopProductTranslation/ShopProductSkuPrice), no menu entry, only accessible via bare URLs
- Zero test coverage: admin/ has no tests/ directory, no phpunit.xml, phpunit ^12.5 only sits in composer require-dev (AUDIT-REPORT.md also admits "Admin automated testing still empty"); php-cs-fixer is in dev dependencies but there's no .php-cs-fixer config, no CI
- i18n not wired into the interface: 5-language translation files exist but the plugin views and controllers have zero trans()/__() calls (grep returns nothing), index.html has no language switch button at the top, inconsistent with CLAUDE.md "LayUI interface text translated via trans() function, language switch button in the top nav bar"

### Risks

- Crud::selectInput returns 6 elements but select() only destructures 5 ($page discarded, pagination depends on Illuminate global request params), doSelect doesn't handle string operators beyond like, and other edge cases, compounded by no tests — high regression risk on future changes

- [Medium] Eliminate the dual-source table list: change InstallController's table conflict list to dynamically generate from parsing install.sql CREATE TABLE, or provide a validation script comparing the two places
- [Low] Wire in i18n: call trans() in views/controllers and add a language switch button at the top of index.html (files ready, only wiring needed), or clarify that i18n only targets service API return values
- [Low] Complete quality tools: add a .php-cs-fixer.php config and wire it into CI (run phpunit + php-cs-fixer --dry-run for admin), taking over the "Admin add tests" follow-up item already listed in AUDIT-REPORT.md

## 3. Flutter Client (apps/flutter/)

### Current Status Summary
The Flutter client skeleton is complete (11 pages, 11 routes, 5-language entries table, Dio three interceptors aligned with backend middleware), but it's in a "browsable demo-level" state: the three transaction loops of ordering/registration/payment are directly rejected by the backend with 422/40001 because address_id and PosterVerify human verification are missing, i18n is wired into only 1 page, and multi-currency doesn't reach through to the API.

### Implemented
- Tech stack and project skeleton genuinely exist: pubspec.yaml/lock pins flutter_riverpod ^2.3.0, go_router ^12.0.0, dio ^5.3.0, responsive_framework, cached_network_image, flutter_secure_storage, shared_preferences, intl ^0.20.2; lib/ has 25 Dart files total, android/ios/macos/linux/windows/web six platform directories all present
- GoRouter configures 11 routes (app_router.dart): /, /products, /product/:id, /cart, /checkout, /orders, /profile, /addresses, /login, /register, /order/:id, corresponding to 11 page files that all genuinely exist
- i18n infrastructure: app_localizations.dart hardcodes 5 languages (zh_CN/zh_HK/en/ja/ko) with 32 translation keys each; locale_provider.dart uses Riverpod StateNotifier + SharedPreferences to persist language/currency, localeProvider/currencyProvider registered
- Dio interceptors aligned with backend middleware: _AuthInterceptor (Bearer token + 401 calls /auth/refresh retry), _LocaleInterceptor (Accept-Language + API-Version headers, matching backend LocaleMiddleware/VersionRoute), _PlatformInterceptor (X-Platform header, matching backend PlatformMiddleware)
- API layer contracts consistent: ApiResponse{code,msg,data} and PaginatedData{list,total,page,per_page} match the backend ApiResponse::success/paginate unified format; apiBaseUrl supports --dart-define override, with Android emulator 10.0.2.2 special case
- home_screen implements PC/tablet responsiveness: >1024 uses NavigationRail sidebar + 4-column grid, narrow screens use NavigationBar bottom tabs + 2-column grid (main.dart defines MOBILE/TABLET/DESKTOP three breakpoints); product_list desktop has a 240px price RangeSlider sidebar on the left
- Product module usable: list supports keyword/category_id/sort params (backend ProductController::index all supported, including price_asc/desc, sales, newest sorting), detail page has SKU ChoiceChip, add-to-cart POST /cart (backend CartController::store validates stock and merges same-SKU quantities); ProductCard clickable into detail
- Cart usable: list fields (id/title/image/price/quantity/selected) match backend CartController::index output, supports DELETE /cart/{id}, checkout entry jumps to /checkout
- Order module basically usable: list (order_no/status_text/pay_amount/currency_code aligned with OrderController::index), detail (with items), cancel POST /orders/{id}/cancel (backend OrderController::cancel exists)
- Address management usable: /user/addresses list/add/delete/set-default aligned with the four backend UserController endpoints, form includes default address flag
- Auth basics usable: login/register call /auth/login, /auth/register and saveTokens to flutter_secure_storage (secure token storage), init() restores login state at startup; AuthService and ApiClient share the same storage key
- Testing and quality tools: test/widget_test.dart smoke test (1 testWidgets verifying ShopApp renders); analysis_options.yaml enables flutter_lints default ruleset

### Gaps
- **Ordering loop broken (fatal)**: CheckoutScreen._placeOrder only submits {currency_code}, but OrderController::store strictly validates address_id (missing → 422 "shipping address does not exist", docs/api.md 5.3 also explicitly requires address_id); and config/poster.php lists /api/orders in protected_routes, the route has PosterVerify middleware attached, and Flutter doesn't send X-Poster-Token → ordering is necessarily rejected with 40001 "human verification required"
- Payment entirely missing: checkout_screen only GETs /payment/methods to show the method list, never calls POST /payment/create and GET /payment/status, no payment initiation/result polling after ordering, inconsistent with docs/features.md 2.2 payment sequence (C→POST /payment/create→SDK payment→webhook)
- Registration blocked by human verification: POST /auth/register is protected by PosterVerify (poster.php config), RegisterScreen doesn't implement X-Poster-Token acquisition/carrying, registration requests necessarily rejected with 40001
- i18n only built as a library, not applied: AppLocalizations.of is actually called only by profile_screen.dart (the only usage in all of lib), the other 11 screens have about 66 hardcoded Chinese/English strings (home 'Home', cart 'Shopping Cart', register 'Please enter email and password', order_detail 'Order cancelled' mixed Chinese/English), the "5-language interface" promise cannot be delivered
- Documentation inconsistent with reality: apps/CLAUDE.md claims "10 routes" but there are actually 11 (extra /order/:id); claims the tech stack includes fl_chart and window_manager, but neither package is in pubspec.yaml/lock; features.md "Flutter 5 platforms" lists 6 platforms
- Multi-currency doesn't reach through to the API: the client currencyProvider is only used for local formatting, product list/detail/cart requests carry no currency param (backend defaults to USD); ProductDetailScreen uses hardcoded '$' and reads product.display_price (backend only attaches display_price at the SKU level, product level is always null) → the VAT-inclusive line never displays
- Pagination and filters incomplete: ProductListScreen's _page never increments, no scroll loading (only the first 20 items visible); OrderListScreen has no pagination; desktop price RangeSlider passes min_price/max_price but backend ProductController::index has no price filter logic at all (only sorting references min_price) → slider ineffective
- Robustness and login state defects: all screens' _load except home have no try/catch, DioException uncaught when not logged in accessing /orders, /user/addresses etc. (loading state stuck/unhandled exceptions); GoRouter has no redirect login guard (redirect-cnt=0), not-logged-in users can reach /cart /checkout /orders /addresses directly; Profile "logout" is context.push('/login') rather than AuthService.logout(), doesn't clear tokens, a functional bug
- Dead code and test gaps: ProductReviewList (product_review_list.dart) is implemented but no page references it, product detail doesn't show reviews; only 1 smoke test, no model/component/integration tests; .github/workflows/ci.yml only covers PHP (phpunit + syntax), no Flutter analyze/test tasks; assets/images directory is empty but pubspec.yaml declares that asset directory

### Risks
- Core transaction chain unusable on the Flutter side: ordering (missing address_id + PosterVerify 40001), payment (no /payment/create), registration (PosterVerify 40001) all rejected by the backend; going live with the current code directly blocks purchase conversion
- No login guard + 401 refresh logic without concurrency deduplication: multiple simultaneous 401s concurrently call /auth/refresh (api_client.dart has no lock), and refresh failure has no logout fallback, token state can become inconsistent
- i18n dual-track (entries table + 66 hardcoded strings) coexisting long-term leads to mixed interface languages, new copy hardcoded directly, the 5-language promise and docs/VERSIONS.md "internationalization ✅" claim undeliverable, rework costs accumulating
- Multi-currency display disconnected from actual payment: the interface can switch to JPY/KRW but prices still display hardcoded in USD and the API still prices in USD, multi-currency settlement amounts won't reconcile, a transaction consistency risk
- No Flutter CI gate and flutter/dart analyze can't run in this environment due to read-only SDK: relying on manual review of 25 files, compile/static regression risk high (historical issues recorded in docs/VERSIONS.md like intl conflicts, pending Timers lack automated protection)

### Suggestions
- [High] Open up the ordering loop: checkout page adds address selection (reusing /user/addresses, default address backfill), submits address_id+currency_code, and integrates the backend PosterVerify flow (obtain X-Poster-Token then POST /orders), then implements the POST /payment/create + GET /payment/status polling payment page
- [High] Fully wire in AppLocalizations: replace the 66 hardcoded strings across 11 screens with translate(key) and fill missing keys (address forms, order statuses, error messages etc.), remove the duplicated definitions in AppTheme.supportedLocales and locale_provider.supportedLocales, unify the single source of truth
- [High] Add GoRouter redirect login guard (not-logged-in access to /cart /checkout /orders /addresses redirects to /login), Profile "logout" changed to call AuthService.logout() then return home, and clean login-state-related page states
- [Medium] Add try/catch and error/empty state UI to all screens' _load (currently only home has exception fallback); ApiClient 401 refresh adds a single-flight lock and failure logout fallback; cart adds quantity +/- (PUT /cart/{id})
- [Medium] Product detail/list requests carry the currency param, prices changed to read sku.display_price or the display_price field, replace all hardcoded '$' with CurrencyFormatter; backend ProductController::index adds min_price/max_price filtering, frontend implements scroll pagination
- [Medium] RegisterScreen and sensitive operations integrate PosterVerify: implement slider/puzzle verification to obtain X-Poster-Token (backend poster verification endpoint or frontend integration), ensuring registration/ordering aren't blocked by 40001
- [Low] Complete Flutter tests: Product/Order model fromJson unit tests, route smoke tests (11 routes reachable), cart/address widget tests, and add GitHub Actions flutter analyze + flutter test tasks (aligned with the PHP ci.yml)
- [Low] Fix documentation and dead code: apps/CLAUDE.md routes 10→11, remove fl_chart/window_manager claims; wire ProductReviewList into the product detail page or delete it; clean up the empty assets/images directory or add placeholder assets

## 4. HarmonyOS Client (apps/harmonyos/)

### Current Status Summary

## 5. Security & Compliance

### Current Status Summary
The platform has real and fairly complete implementations of WAF attack detection, JWT dual tokens, AES interface encryption, Encryptable field encryption, Hashids obfuscation, payment webhook signature verification, and key management (all 22 tests pass), but the risk rule engine, KYC, and GDPR/CCPA execution layers have only table structures and admin-side CRUD, with core business logic missing, inconsistent with the "complete/✅" claims in docs/features.md and docs/VERSIONS.md.
