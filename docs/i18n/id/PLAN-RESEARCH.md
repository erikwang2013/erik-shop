## 1. API Bisnis Server (service/)

### Ringkasan Status
Fondasi arsitektur dan keamanan/pembayaran/pencarian/rekomendasi kokoh (39 controller + 111 model + 14 middleware + 10 tugas terjadwal, Stripe/PayPal benar-benar dapat digunakan、22 unit test lolos), tetapi sejumlah kemampuan yang diklaim "lengkap" di dokumentasi sebenarnya placeholder atau belum terhubung: gateway Klarna/Adyen hanya konfigurasi, order belum menghitung kupon/ongkir/bea/risiko, pemisahan baca/tulis belum diaktifkan, data seed bisnis hilang menyebabkan antarmuka inti instalasi baru tanpa data.

### Sudah Diimplementasikan
- Implementasi ganda gateway pembayaran (kode asli): di PaymentGateway.php Stripe (PaymentIntent + verifikasi tanda tangan webhook + refund) dan PayPal (REST v2 OAuth2 + order/capture/refund + verifikasi tanda tangan lima field verify-webhook-signature + parsing capture id refund) lengkap dapat dijalankan, PaymentController::webhook menggunakan gerbang atomik status pesanan mencegah pencatatan berulang dan membuat catatan pembagian dana PlatformSettlements dalam transaksi
- Loop tertutup rantai pembayaran: PaymentController (create/status/methods/webhook)、AdminOpsController::executeRefund benar-benar menjalankan refund gateway dan menyimpan transaksi (catatan refund + catatan pembayaran + status pesanan + log)、PaymentReconcileCron setiap 6 jam merekonsiliasi dokumen menunggu pembayaran lebih dari 2 jam sesuai status asli gateway
- Tumpukan middleware 14 berurutan berlaku (config/middleware.php): Cors→Security(25+ jenis detektor SecurityGuard security-php + penghitung brute force Redis)→RateLimit(jendela geser Redis, 6+ aturan endpoint)→Platform(pengenalan 8 platform)→GeoIp(MaxMind)→Locale→HashidsDecode→VersionRoute(header API-Version)→HashidsEncode→Encryption, tingkat rute PosterVerify/JwtAuth/AdminKey
- Penetapan harga multi-mata uang dan produk multibahasa benar-benar diimplementasikan: ProductSkuPrices penetapan harga independen per mata uang + degradasi nilai tukar ExchangeRates、ProductTranslations eager load per locale (ProductController menyertakan perhitungan harga tampilan termasuk/tidak termasuk pajak VAT)
- Estimasi bea masuk benar-benar dapat digunakan: TariffController menghitung duty/vat sesuai ProductHsCodes→TariffRules(dest_country+hs_code)→VatSettings (termasuk ambang bebas pajak dan disclaimer); ShippingController menghitung ongkir sesuai zona logistik + tingkatan berat
- Pencarian dan rekomendasi benar-benar diimplementasikan: SearchController melalui webman-scout (model Products Searchable + pemetaan ES erik_shop_products) degradasi MySQL LIKE saat ES abnormal dan menulis SearchLogs; RecommendationCron menghitung co-occurrence pembelian 90 hari terakhir menulis Top10 ke product_recommendations, RecommendationController item-based CF + degradasi populer
- Alur inti pesanan: store pengurangan stok atomik dalam transaksi (where stock>=qty decrement, cegah oversell)、pembatalan memulihkan stok、titik masuk blokir KYC/larangan jual、mesin status 0-8; CouponController::claim kunci baris lockForUpdate + gerbang atomik cegah klaim berlebih
- 10 tugas terjadwal semuanya terdaftar di config/process.php (nilai tukar/lacak logistik/Feed/rekomendasi/kepatuhan/timeout retur/pengingat harga/rekonsiliasi pembayaran/pembagian dana/sinkronisasi multi-platform), semuanya dengan log error dan logika skip saat belum dikonfigurasi
- Ekspor dokumen benar-benar dapat digunakan: ExportController PhpSpreadsheet XLSX+CSV (termasuk kolom HS Code)、DocumentController faktur komersial/daftar pengepakan (dompdf)、HealthController pengecekan liveness (periksa ganda db/redis)
- Toolchain kualitas lengkap: PHPUnit 12.5 (22 tests/45 assertions, 4 file Security/Jwt/ApiResponse/RedisFacade)、phpstan level 5 (phpstan.neon berisi pengecualian false positive Eloquent)、php-cs-fixer、.github/workflows/ci.yml (matriks PHP 8.3/8.4 + MySQL + Redis)
- Pola infrastruktur benar-benar diterapkan: primary key Snowflake BaseModel、middleware encode/decode Hashids konversi otomatis、Jwt.php access/refresh token ganda (JwtAuth menolak refresh untuk antarmuka bisnis)、enkripsi field encryptable、config/risk.php+country.php+geoip.php konfigurasi operasional lengkap

### Kesenjangan
- Klarna/Adyen/Afterpay hanya placeholder: match PaymentGateway::make() hanya mendukung stripe/paypal (default lempar pengecualian), filter eksplisit PaymentController::methods hanya mengembalikan stripe/paypal (komentar mengakui "menghindari mengekspos gateway yang belum diimplementasikan"); tetapi contoh respons docs/api.md 6.1 berisi baris Klarna、features.md 1.0 mengklaim Klarna BNPL/Adyen, dokumen dan kode tidak sesuai
- Order belum mengintegrasikan kupon/ongkir/bea/risiko: OrderController::store hanya menjumlahkan subtotal produk, tidak membaca coupon_id yang didokumentasikan (api.md 5.3), tidak menghitung field shipping_fee/tax_amount/discount_amount/insurance_fee yang sudah ada di erik_orders; config/risk.php ada tetapi tidak ada panggilan RiskEngine apa pun di app/ (features.md 3.3 mengklaim "menghitung harga (per mata uang + kupon)" dan "penilaian risiko (RiskEngine::score)")
- Data seed bisnis hilang: install.sql hanya 2 INSERT (tabel sistem wa_options/wa_roles), erik_hs_codes/erik_tariff_rules/erik_payment_gateway_methods/erik_shipping_zones/erik_countries semuanya tanpa data; database/seeders hanya countries.php dan tidak ada kode yang memuatnya (file mati, CLAUDE.md mengklaim mencakup negara/HS Code/nilai tukar/zona logistik/kategori kepatuhan/tabel ukuran/aturan risiko) — setelah instalasi baru antarmuka countries/payment methods/ongkir/bea mengembalikan kosong
- Konfigurasi pemisahan baca/tulis belum diaktifkan: config/database.php mendefinisikan mysql_rw (2 replika baca + sticky) tetapi tidak ada kode di app/ dan config/ yang mereferensikan nama koneksi tersebut, semua model memakai default mysql; klaim features.md 5.x "DB pemisahan baca/tulis (2 replika baca+sticky) lengkap" tidak sesuai kenyataan
- Pembelian berlangganan dan listing produk multi-platform hanya struktur tabel: model Subscriptions/SubscriptionOrders/SubscriptionLogs、PlatformListings ada tetapi tanpa controller/routing/kode penulisan (multi-platform hanya PlatformOrderSyncCron yang bergantung URL eksternal untuk menarik order); features.md mengklaim keduanya "lengkap"
- Pernyataan berlebihan pencarian multibahasa ES: CLAUDE.md mengklaim "indeks ES berisi title/description semua bahasa dan diberi bobot per locale", tetapi Products::toSearchableArray() hanya mengindeks field dasar satu bahasa; direktori app/search/ yang diklaim CLAUDE.md sebenarnya tidak ada (Searchable inline di model)
- IM WebSocket layanan pelanggan belum diimplementasikan: hanya struktur tabel ChatSessions/ChatMessages (features.md mengakui "WS menunggu implementasi", konsisten tetapi memang belum selesai), dan mesin status pesanan "menunggu review (8)/refund berjalan (6)" tidak memiliki jalur penulisan apa pun (tidak ada alur review, refund hanya admin executeRefund langsung ke sudah refund (7))
- Cakupan pengujian sempit dan berbeda dengan pernyataan dokumen: hanya 4 file unit test (AUDIT-REPORT.md mengakui "tanpa pengujian integrasi/tanpa laporan cakupan"), tanpa pengujian integrasi controller/order/pembayaran/middleware; api.md 13.18 menyebut ekspor mengembalikan CSV, kode sebenarnya default XLSX + CSV opsional; parameter filter min_price/max_price yang didokumentasikan api.md 2.1 belum diimplementasikan di ProductController::index

### Risiko
- Rantai pembayaran kurang idempotensi dan cakupan event: POST /api/payment/create tanpa kunci idempoten, permintaan berulang menghasilkan banyak catatan menunggu pembayaran; webhook hanya menangani payment_intent.succeeded / PAYMENT.CAPTURE.COMPLETED, event refunded/failed dll. diabaikan diam-diam, bergantung fallback PaymentReconcileCron (hanya memeriksa dokumen lebih dari 2 jam)
- Drift dua sumber cakupan pembagian dana: webhook dan SettlementCron masing-masing membaca tarif dari config('payment.gateway_fee.*') dan config('cron.payment_gateway_fee_*'), dua tempat dipelihara independen; dan setelah webhook membuat PlatformSettlements(status=0), SettlementCron menghitung ulang dengan dedup berdasarkan order_id, terdapat risiko duplikasi/inkonsistensi cakupan; pembagian dana hanya komisi platform + biaya gateway, supplier_amount tanpa alur pembayaran、affiliate_amount selalu 0, settlement pembagian dana multi-mata uang (docs/08-multi-currency-settlement) tidak loop tertutup
- Deployment baru langsung data kosong + kepatuhan default lolos: seed bisnis semua hilang dan config/country.php blocked_countries default array kosong、kyc_required_countries hanya KR, blokir larangan jual/KYC OrderController bergantung konfigurasi manual, salah konfigurasi berarti sepenuhnya terbuka
- Ketergantungan pencarian rapuh: saat ES tidak tersedia seluruh bagian try/catch degradasi MySQL LIKE, sinkronisasi scout tanpa queue (config/scout.php sync.queue=false), indeks dan penganalisis multibahasa tanpa cakupan CI, drift indeks tidak terkendali
- Celah presisi keuangan dan mesin status: jumlah pesanan diakumulasi round dengan float; refund hanya status=7 seluruh pesanan tanpa refund parsial; mesin status Refunds 2(tolak)/3(sudah refund) hanya bertransisi di satu jalur AdminOpsController, tanpa aplikasi refund sisi pengguna dan antarmuka review (bagian review/lembar alur retur features.md 3.5 bergantung sisi admin)

## 2. Panel Admin (admin/)

### Ringkasan Status
Panel admin berbasis webman-admin + LayUI/Pear Admin telah memiliki wizard instalasi lengkap、izin RBAC、tumpukan middleware WAF dan kerangka 82 controller/76 model, tetapi lapisan bisnis "ada controller tanpa halaman": dari 67 controller toko, 59 adalah stub CRUD murni yang hanya mengikat model、tanpa view HTML apa pun selain panel lintas batas (klik menu 404), dan dua controller ShopOrder/ShopPayment langsung error fatal saat load class di PHP 8.3 karena tanda tangan metode tidak kompatibel, menu order/pembayaran sebenarnya tidak dapat digunakan.

### Sudah Diimplementasikan
- 82 controller (15 sistem + 67 shop) dan 76 model (9 sistem + 67 shop) semuanya berpasangan dan memiliki header Copyright, namespace mengikuti plugin\admin\app\controller|model
- Kelas dasar CRUD generik Crud lengkap mengimplementasikan select/insert/update/delete dan pemformatan tree/select/normal, termasuk izin data (dataLimit: personal/auth)、filter inputFilter daftar putih field struktur tabel desc、hash password、titik ekstensi afterQuery/insertInput/updateInput, dll.
- Wizard instalasi Web InstallController benar-benar dapat digunakan: step1 buat database + validasi tabel konflik + impor install.sql root (117 tabel) + membuat plugin/admin/config/database.php dan thinkorm.php + membuat service/.env dan admin/.env (JWT/Hashids/AES/ADMIN_API_KEY acak) + reload SIGUSR1; step2 membuat super admin dan mengikat peran 1; importMenu mengimpor config/menu.php secara rekursif ke wa_rules
- Sistem izin lengkap: middleware AccessControl + plugin\admin\api\Auth::canAccess (noNeedLogin/noNeedAuth/pencocokan aturan peran/wildcard * super admin/pembagian 401 dan 403), bergantung tabel wa_roles/wa_rules/wa_admin_roles
- Tumpukan middleware konsisten dengan features.md 4.2: SecurityMiddleware (SecurityGuard erikwang2013/security-php + brute force login 5 kali/300s + header respons keamanan)、PlatformMiddleware (pengenalan UA 8 platform)、HashidsDecode/HashidsEncode (dekode permintaan dan encode field respons *_id)、AccessControl
- Struktur menu config/menu.php (526 baris): 6 grup sistem + 7 grup bisnis analisis data/manajemen toko/manajemen order/bea cukai & pajak/manajemen logistik/manajemen pemasaran/manajemen rantai pasok total 27 item menu toko, termasuk bobot/ikon/routing
- Panel lintas batas ShopDashboardController + view ECharts (tema Pear Admin, kartu KPI dan 5 kontainer grafik, mereferensikan CDN echarts@5.5.0)
- Persetujuan refund ShopRefundController adalah salah satu dari sedikit controller berisi logika bisnis nyata: mesin status 0 menunggu/1 lolos/2 tolak/3 sudah refund, sebelum menandai sudah refund memanggil antarmuka internal service POST /api/admin/refunds/{id}/execute (otentikasi X-Admin-Key, sisi service AdminOpsController + AdminKeyMiddleware benar-benar ada), kegagalan menolak penyimpanan
- Ekspor order ShopExportController: PhpSpreadsheet membuat Excel (nomor order/tanggal/status/mata uang/jumlah produk/diskon/ongkir/jumlah terbayar), barryvdh/laravel-dompdf membuat PDF faktur komersial (termasuk detail、mata uang、peringatan deklarasi bea cukai)
- Model seragam berdasarkan primary key Snowflake (Base::boot creating otomatis membuat ID tipe string), model bisnis mendeklarasikan nama tabel erik_ dan berbagi koneksi MySQL yang sama dengan service (plugin.admin.mysql)
- File dasar i18n ada: di admin/resource/translations zh_CN/zh_HK/en/ja/ko lima bahasa masing-masing 48 kunci
- Kualitas dan deployment pendukung: composer.json berisi dependensi dev phpunit ^12.5 dan php-cs-fixer, admin/Dockerfile + docker-compose (port 8788) konfigurasi lengkap

### Kesenjangan
- **Cacat fatal (sudah direproduksi terukur)**: ShopOrderController.php dan ShopPaymentController.php menimpa metode kelas dasar Crud dengan tanda tangan tidak kompatibel (kurang tipe kembalian : array / : Response), PHP 8.3 langsung Fatal error saat load class——item menu「Daftar Order」「Catatan Pembayaran」begitu diakses langsung crash, dan akan ikut membuat proses webman error
- Dari 67 controller toko, 59 adalah stub CRUD murni yang hanya berisi protected $model, dan selain ShopDashboardController tidak ada metode index() dan view HTML apa pun (di view/shop/ hanya satu file dashboard/index.html); href menu /app/admin/shop/ShopProduct/index, dll. menunjuk action yang tidak ada, setelah pencocokan tepat default routing webman jatuh ke fallback 404——seluruh UI manajemen toko (produk/kategori/logistik/pemasaran, dll.) sebenarnya tidak dapat digunakan, hanya JSON API
- Rantai data panel lintas batas rusak ganda: view fetch /app/admin/shop/shop-dashboard/kpi dan /chartData (penulisan kebab) tanpa routing yang sesuai (nama kelas ShopDashboardController, sudah diverifikasi webman App::getController mencocokkan tepat sesuai nama file); dan ShopDashboardController::kpi/chartData memanggil $this->json(['code'=>0,...]) meneruskan array, bertentangan dengan tanda tangan Base::json(int $code,...) pasti lempar TypeError; tiga grafik distribusi wilayah/rasio mata uang/status pesanan adalah data contoh hardcoded (komentar kode menandai「contoh data」), grafik「waktu logistik」yang diklaim CLAUDE.md tidak ada
- Klaim dokumen tidak sesuai dengan kode: PDF daftar pengepakan、PDF laporan keuangan (ringkasan per mata uang) tidak ada implementasi apa pun di admin; manajemen pengiriman ShopShipmentController murni stub (tanpa logika deklarasi HS dan lacak); kolom ekspor Excel order (baris 44-60 ShopExportController.php) tanpa kolom HS Code/bea, tidak sesuai dengan CLAUDE.md「berisi HS Code/bea/mata uang」; produk「edit multibahasa + penetapan harga per mata uang」tanpa UI yang sesuai (ShopProductTranslation/ShopProductSkuPrice adalah stub dan tidak ada di menu)
- 40 controller shop tidak ada di menu.php (ShopMerchant/ShopPlatformAccount/ShopPlatformListing/ShopPlatformOrder/ShopRiskRule/ShopRiskLog/ShopCms/ShopGiftCard/ShopMembership/ShopPointRule/ShopSubscription/ShopB2b/ShopAbTest/ShopCountry/ShopCurrency/ShopExchangeRate/ShopEmailTemplate/ShopNotification/ShopOperationLog/ShopUserKyc/ShopSetting/ShopOrderDocument/ShopSizeChart/ShopKnowledgeBase/ShopFaq/ShopProductAttr/ShopProductCompliance/ShopProductFeed/ShopPriceAlert/ShopPrivacy/ShopInsurance/ShopInventoryTransfer/ShopApiDoc/ShopShop/ShopMerchantProduct/ShopMerchantSettlement/ShopCountryCompliance/ShopProductHsCode/ShopProductTranslation/ShopProductSkuPrice), tanpa pintu masuk menu hanya bisa diakses URL telanjang
- Cakupan pengujian nol: admin/ tanpa direktori tests/、tanpa phpunit.xml, phpunit ^12.5 hanya berhenti di composer require-dev (AUDIT-REPORT.md juga mengakui「Otomatisasi pengujian sisi Admin masih kosong」); php-cs-fixer ada di dependensi dev tetapi tanpa konfigurasi .php-cs-fixer, tanpa CI
- i18n belum terhubung ke antarmuka: 5 file terjemahan bahasa ada, tetapi view plugin dan controller tanpa panggilan trans()/__() apa pun (grep tanpa hasil), index.html atas tanpa tombol beralih bahasa, tidak sesuai dengan CLAUDE.md「teks antarmuka LayUI diterjemahkan melalui fungsi trans()、tombol beralih bahasa terletak di bilah navigasi atas」
- Logika blokir insert/update/delete ShopPaymentController yang dimaksudkan「catatan pembayaran read-only」sepenuhnya tidak efektif karena error tanda tangan; batasan bisnis「tidak mengizinkan membuat/mengubah order langsung」ShopOrderController yang dimaksudkan juga tidak dapat berlaku

### Risiko
- Level pemblokiran peluncuran: ShopOrderController/ShopPaymentController langsung Fatal error saat load class (terukur PHP 8.3), dua menu daftar order/catatan pembayaran begitu dibuka langsung error, dan error fatal PHP akan membuat seluruh proses memori tetap webman error restart
- Stub controller banyak (59/67) + menu dan dokumen mengklaim fungsi lengkap, mudah membuat pengembang/ops salah menilai fungsi sudah diluncurkan (menu ada、tabel ada、API namun 404 atau data kosong), termasuk utang teknis sangat menyesatkan
- HashidsEncode melakukan encode semua string angka *_id/id dalam respons (termasuk cabang ambang int di bawah 40000 tidak di-encode), jika di masa depan field bisnis baru salah masuk encodeFields atau ada ID angka non-snowflake di tabel, akan membuat semantik ID frontend-backend kacau dan tanpa jaring pengaman pengujian
- Daftar tabel konflik $tables_to_install yang di-hardcode install.sql dan InstallController (sekitar 117 item) dipelihara di dua tempat, saat menambah tabel deteksi konflik sangat mudah lupa diubah, jika install.sql berisi stored procedure/trigger juga mungkin dirusak splitSqlFile yang memotong berdasarkan titik koma (SQL saat ini tidak terlihat konten seperti itu, termasuk risiko potensial)
- Crud::selectInput mengembalikan 6 elemen sedangkan select() hanya mendestruktur 5 ($page dibuang, paginasi bergantung parameter global permintaan Illuminate)、doSelect belum menangani operator string selain like, ditambah tanpa pengujian, risiko regresi perubahan berikutnya tinggi

## 5. Keamanan dan Kepatuhan

### Ringkasan Status
Platform memiliki implementasi nyata dan relatif lengkap dalam deteksi serangan WAF、JWT token ganda、enkripsi antarmuka AES、enkripsi field Encryptable、obfuscation Hashids、verifikasi tanda tangan Webhook pembayaran dan manajemen kunci (22 pengujian semua lolos), tetapi mesin aturan risiko、KYC、lapisan eksekusi GDPR/CCPA hanya struktur tabel dan CRUD sisi admin, logika bisnis inti hilang, tidak sesuai dengan klaim "lengkap/✅" docs/features.md、docs/VERSIONS.md.

### Sudah Diimplementasikan
- Deteksi serangan WAF: SecurityMiddleware service dan admin sama-sama membungkus erikwang2013/security-php v1.1.6 SecurityGuard, config/plugin/erikwang2013/security-php/app.php mengonfigurasi 31 detektor (28 block、3 log: header_injection/ssti/nosql_injection), termasuk XSS/SQLi/XXE/SSRF/path traversal/unggah file/CSRF/Host/DNS rebinding, dll., plus daftar hitam IP (5 kali/60s→larangan 900s)、header respons keamanan (nosniff/DENY/Permissions-Policy/penyembunyian Server)
- Perlindungan brute force: penghitung Redis erik_brute:{ip}:{login|register} sisi service 10 kali/60s (SecurityMiddleware::checkBrute), sisi admin 5 kali/300s
- Autentikasi JWT: config/jwt.php (HS256、access 7200s/refresh 1209600s、issuer/audience/leeway), app/common/Jwt.php kunci kosong fail-closed (rantai fallback JWT_SECRET→JWT_SECRET_KEY), middleware JwtAuth menolak token non-access type, AuthController registrasi/login menerbitkan token ganda、endpoint refresh memutar token ganda (firebase/php-jwt v6.11.1 terkunci)
- Enkripsi antarmuka AES: app/common/Encryption.php (AES-256-CBC、IV acak setiap kali、base64(iv+ciphertext)、validasi panjang kunci 16/24/32 byte), EncryptionMiddleware mendukung dekripsi permintaan X-Encrypted:1、enkripsi field respons X-Encrypt-Response:1/X-Encrypt-Fields, melewati /api/health、/api/ping、/apidoc, terdaftar sebagai tingkat akhir tumpukan middleware global

- Pembayaran Klarna/Adyen belum diimplementasikan: PaymentGateway::make() hanya mendukung stripe/paypal (service/app/common/PaymentGateway.php), PaymentController.php:34 komentar jelas 'hanya mengembalikan gateway yang sudah diimplementasikan, menghindari mengekspos konfigurasi yang belum diimplementasikan seperti Klarna/Adyen', tetapi README.md dan VERSIONS.md mencantumkannya sebagai ✅, hanya features.md yang mengakui 'Stripe lengkap, lainnya placeholder'
- PDF faktur komersial/daftar pengepakan belum diimplementasikan: composer.json berisi barryvdh/laravel-dompdf tetapi seluruh proyek (service/admin) nol panggilan Dompdf; DocumentController.php hanya membaca catatan erik_order_documents yang ada, tanpa logika pembuatan apa pun (catatan order_documents juga tidak akan dibuat otomatis), tetapi features.md mengklaim 'PDF faktur komersial/daftar pengepakan' lengkap
- Mesin aturan risiko belum diimplementasikan: dari 8 kelas app/common tidak ada RiskEngine, OrderController::store tanpa penilaian risiko, status order 8 (menunggu review) tidak pernah ditulis; features.md mengklaim 'mesin aturan (penilaian side-channel: validasi alamat/pencocokan kode pos/3DS/registrasi massal/anomali nilai barang) lengkap' dan mesin status pesanan berisi cabang 'menunggu pembayaran→menunggu review: skor risiko tinggi', aktualnya tidak dapat dicapai
- Pembagian dana empat jalur hanya mengimplementasikan satu jalur: webhook dan SettlementCron hanya membuat PlatformSettlements; MerchantSettlements/SupplierSettlements/AffiliatePayouts seluruh proyek tanpa penulisan ::create apa pun (hanya tabel + CRUD admin), diagram README dan 08-multi-currency-settlement mengklaim 'empat jalur settlement independen'
- Pembelian berlangganan dan AB test tanpa API server (hanya tabel + controller CRUD admin, route.php tanpa route yang sesuai); 'Amazon/eBay/Shopee/Lazada/Temu listing produk + agregasi order' multi-platform tanpa integrasi platform nyata, hanya PlatformOrderSyncCron menarik sesuai URL generik (PlatformListings tanpa penulisan bisnis); IM WebSocket belum diimplementasikan tetapi VERSIONS.md menandai ✅ (features.md/README sudah jujur menandai)
- Buku besar stok tidak dapat diubah belum diterapkan: InventoryLogs tanpa penulisan bisnis apa pun (pengurangan stok order tidak mencatat riwayat); tabel laba/rugi kurs CurrencyExchangeGainsLosses juga tanpa logika penulisan, 'riwayat stok (buku besar tidak dapat diubah)' dan 'pelacakan laba/rugi kurs' yang diklaim README hanya berhenti di lapisan struktur tabel
- Data seed tidak diimpor bersama instalasi: install.sql hanya berisi struktur tabel dan seed sistem wa_ (wa_options/wa_roles), data dasar countries/currencies/payment_gateway_methods/hs_codes/shipping_zones perlu menjalankan manual service/database/seeders/countries.php (InstallController hanya mengimpor install.sql), setelah instalasi baru produk/metode pembayaran/perhitungan ongkir keluar kotak kosong; tetapi AUDIT-REPORT menandai 'data seed database OK'
- Dokumen dinamis hg/apidoc tidak sesuai nama: hanya AuthController + ProductController yang memiliki anotasi @Apidoc (59 baris), 36 controller lainnya nol anotasi, cakupan dokumen 6 grup otomatis sangat tidak cukup; dan ada penyimpangan angka (controller admin aktual 80 vs dokumen 82、sumber HarmonyOS 13 vs dokumen 14、terjemahan 45 vs AUDIT menyebut 48、diagram pipa middleware features.md melewatkan RateLimit/Encryption)

### Risiko
- Dokumentasi sistematis membesar-besarkan tanda 'lengkap' (multi-platform、mesin risiko、langganan/AB、pembagian dana empat jalur、PDF faktur、Klarna/Adyen、WS layanan pelanggan), membentuk kesenjangan ekspektasi pengiriman fitur bagi pelanggan lisensi komersial, ada risiko kontrak dan kepercayaan
- Setelah instalasi baru data dasar kosong (seed tidak diimpor otomatis、wizard tidak menjalankan seeder), tabel data inti countries/currencies/payment_gateway_methods tanpa data, jalur utama daftar produk、metode pembayaran、perhitungan ongkir/bea keluar kotak tidak dapat digunakan
- Cakupan dokumen API dinamis hanya 2/38 controller, docking klien Flutter/HarmonyOS kekurangan dasar antarmuka otoritatif; dokumen statis docs/api.md dan route.php ada risiko drift endpoint (71 vs 73, dan diagram pipa internal features.md tidak konsisten)
- Cakupan pengujian hanya 22 unit test (keamanan + JWT + respons + Redis), 38 controller bisnis nol pengujian、admin tanpa pengujian、tanpa pengujian integrasi dan laporan cakupan, risiko regresi refactor/upgrade massal tinggi
- payment_gateway_methods di DB masih berisi baris gateway yang belum diimplementasikan seperti klarna/adyen, saat konfigurasi salah diaktifkan frontend dapat menampilkan tetapi setelah order tanpa pemrosesan gateway, rantai pembayaran ada titik kegagalan tersembunyi
