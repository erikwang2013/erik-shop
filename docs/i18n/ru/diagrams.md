## 7. Архитектура безопасности

![Архитектура безопасности](diagrams/07-security-architecture.svg)

### Обзор защиты

| Уровень | Линия обороны | Технология/пакет | Область покрытия |
|------|------|---------|---------|
| Первый уровень | Сетевой периметр | Nginx SSL + обратный прокси + проверка Host | Service + Admin |
| Второй уровень | Обнаружение атак WAF | 31 детектор `erikwang2013/security-php` | XSS/SQLi/CRLF/обход пути/XXE/SSRF/загрузка файлов/методы/Host/Content-Type/Body и др. |
| Третий уровень | Контроль трафика + устойчивость зависимостей | RateLimitMiddleware + счётчики перебора в Redis + CircuitBreaker | Токен-бакет (6 конечных точек) + защита входа/регистрации от перебора + предохранитель платежей/входа через соцсети (5 сбоев → 30s, полуоткрытое восстановление) |
| Четвёртый уровень | Аутентификация | PosterVerify + JwtAuth HS256 | Человеко-машинная проверка (слайдер/пазл/клик) + Bearer Token + обновление пары токенов |
| Пятый уровень | Безопасность данных | Hashids + AES-256-CBC + Encryptable | Три уровня шифрования: обфускация ID/шифрование передачи/шифрование полей БД |
| Шестой уровень | Безопасность ответов | HTTP-безопасные заголовки + маскирование чувствительных данных | nosniff/DENY/XSS-Protection/Referrer-Policy/маскирование логов |
| Постоянно | Аудит и трассировка | PlatformMiddleware + OperationLogs | Трекинг 8 платформ + запись в 6 таблиц + журнал операций |

## 8. Схема мультивалютных расчётов

![Схема мультивалютных расчётов](diagrams/08-multi-currency-settlement.svg)

### Пояснения к мультивалютным расчётам

**Мультивалютное ценообразование**: SKU товаров оценивается по каждой валюте через `currency_code`; при оформлении заказа фиксируется валюта получения оплаты (USD / EUR / GBP / CNY и т. д.).

**Сервис курсов валют**: таблица курсов `erik_exchange_rates` поддерживает ручное ведение (manual) и автоматическую загрузку через exchangerate-api; курсы версионируются по времени действия `effective_at`; при расчётах используется снимок курса на момент оплаты.

**Списание в исходной валюте**: Stripe / PayPal / Klarna / Adyen списывают средства в валюте заказа; после проверки подписи Webhook и подтверждения зачисления обновляются статусы платежа и заказа.

**Расщепление расчётов**: после успешной оплаты автоматически формируются расчёты платформы `PlatformSettlements` (сумма заказа + комиссия платформы + комиссия платёжного шлюза, учёт в валюте заказа); расчёты продавца `MerchantSettlements` (сумма заказа → ставка комиссии → сумма расчёта), расчёты поставщика `SupplierSettlements`, выплаты партнёрских комиссий `AffiliatePayouts` — четыре независимые линии расчётов, статус 0 — ожидает расчёта / 1 — рассчитано.

**Курсовые разницы**: `CurrencyExchangeGainsLosses` отслеживает разницу между валютой получения и валютой расчёта, сравнивая курс на момент оплаты и на момент расчёта; положительное значение = курсовая прибыль, отрицательное = курсовой убыток; это обеспечивает мультивалютную сверку и аудит для трансграничной торговли.

## Индекс схем

| № | Название схемы | Тип | Назначение |
|------|------|------|------|
| 1 | Системная архитектура | Архитектура | Общий вид системы: клиент → доступ → приложение → данные → внешние сервисы |
| 2 | Схема обработки запросов | Поток | Полный путь HTTP-запроса через конвейер из 12 промежуточных ПО (10 глобальных + 2 маршрутных) |
| 3 | Обзор функциональных модулей | Функции | 17 крупных функциональных модулей и их детальные функции |
| 4 | Жизненный цикл запроса | Жизненный цикл | Полная последовательность от запроса до ответа и взаимодействие этапов |
| 5 | Жизненный цикл заказа | Жизненный цикл | Все переходы статусов заказа от корзины до завершения/возврата |
| 6 | Архитектура развёртывания | Архитектура | Оркестрация контейнеров Docker Compose, сеть, граничный слой CDN (origin-pull) и персистентные тома данных (admin_uploads/service_public) |
| 7 | Архитектура безопасности | Архитектура | 6-уровневая система глубокой обороны: граница → WAF → трафик/устойчивость (ограничение частоты + предохранитель) → аутентификация → данные → ответ |
| 8 | Схема мультивалютных расчётов | Поток | Полная цепочка: ценообразование по валютам → оплата → расщепление → расчёты → курсовые разницы |
